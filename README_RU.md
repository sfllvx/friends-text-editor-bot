# Приватный Telegram-бот для редактирования текста

Бот предназначен для небольшой группы друзей. Поддерживает русский и английский, три стиля (Natural, Academic, Professional), дневные лимиты и доступ по Telegram ID. Текстовые сообщения отправляются в Gemini API для обработки. Бот не сохраняет исходные тексты в своей базе.

> Это редактор для естественности, ясности и стиля. Он не гарантирует прохождение ИИ-детекторов. Проверяйте важные факты и ссылки самостоятельно.

## Что понадобится

- Telegram-аккаунт;
- аккаунт GitHub;
- аккаунт Cloudflare;
- API key из Google AI Studio / Gemini API с доступной бесплатной квотой;
- компьютер для первоначальной настройки (после запуска бот работает без вашего компьютера).

Бесплатные тарифы и доступность моделей могут меняться. Если выбранная модель недоступна в бесплатном тарифе вашего аккаунта, измените `GEMINI_MODEL` в `wrangler.toml` на модель, доступную в Google AI Studio.

## Шаг 1. Создайте Telegram-бота

1. В Telegram откройте `@BotFather`.
2. Отправьте `/newbot` и следуйте подсказкам.
3. Сохраните выданный токен в безопасном месте. **Не публикуйте его в GitHub и не отправляйте друзьям.**
4. Каждый участник должен узнать свой Telegram numeric ID через надёжного ID-бота, например `@userinfobot`. Сверьте ID с человеком лично.

## Шаг 2. Получите Gemini API key

1. Откройте Google AI Studio: https://aistudio.google.com/ .
2. Создайте API key.
3. Не вставляйте ключ в исходный код или сообщения Telegram. Он будет сохранён как секрет Cloudflare.
4. Перед отправкой личных или учебных текстов ознакомьтесь с актуальными условиями обработки данных Google.

## Шаг 3. Создайте Cloudflare Worker и KV

1. Войдите в https://dash.cloudflare.com/ .
2. Откройте **Workers & Pages** и включите адрес `workers.dev`, если Cloudflare попросит.
3. Откройте **Storage & databases → KV** (название раздела может немного отличаться) и создайте namespace с именем `USER_DATA`.
4. Скопируйте ID созданного KV namespace.
5. В репозитории откройте `wrangler.toml` и замените `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` на этот ID.
6. Если нужно, поменяйте имя Worker в строке `name`. Оно должно быть уникальным в вашем аккаунте.

## Шаг 4. Загрузите проект в GitHub

1. Создайте новый **Private** repository на https://github.com/new . Не делайте репозиторий публичным. Можно назвать его `friends-text-editor-bot`; не добавляйте README или лицензию автоматически, чтобы репозиторий был пустым.
2. Скачайте и установите **GitHub Desktop**: https://desktop.github.com/ , войдите в аккаунт GitHub и выберите **File → Clone Repository**, затем клонируйте созданный пустой репозиторий в удобную папку на компьютере.
3. Распакуйте скачанный ZIP проекта. Скопируйте всё его содержимое, включая скрытую папку `.github`, в папку клонированного репозитория. Важно: копируйте содержимое папки проекта, а не саму внешнюю папку.
4. В GitHub Desktop проверьте, что появились файлы `wrangler.toml`, `src/index.js` и `.github/workflows/deploy.yml`. Введите сообщение коммита, нажмите **Commit to main**, затем **Push origin**.
5. GitHub Actions может попросить разрешение на запуск workflow. Разрешите его.

## Шаг 5. Создайте секреты Cloudflare и GitHub

### Cloudflare Worker secrets

В Cloudflare откройте Worker после первого успешного deploy и добавьте следующие **Secrets** (не обычные vars):

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка из букв, цифр, `_` и `-`, например сгенерируйте её в менеджере паролей;
- `GEMINI_API_KEY` — ключ Google AI Studio;
- `ALLOWED_TELEGRAM_IDS` — ID пользователей через запятую, например `111111111,222222222`.

Секреты Worker можно задать в настройках Worker → Settings → Variables and Secrets. После изменения secrets выполните новый deploy из GitHub Actions.

### GitHub repository secrets

Откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте (для самого первого deploy можно сначала добавить первые два секрета, а остальные добавить после того, как узнаете URL Worker):

- `CLOUDFLARE_API_TOKEN` — токен Cloudflare API с правами на Workers Scripts: Edit и аккаунт;
- `CLOUDFLARE_ACCOUNT_ID` — Account ID из панели Cloudflare;
- `TELEGRAM_BOT_TOKEN` — тот же токен BotFather;
- `TELEGRAM_WEBHOOK_SECRET` — точно та же строка, что и в Cloudflare Worker;
- `WORKER_URL` — полный URL Worker, например `https://friends-text-editor-bot.YOUR-SUBDOMAIN.workers.dev` (без завершающего `/`).

Не добавляйте реальные ключи в `wrangler.toml`, `README`, код или коммиты. Если секрет случайно опубликован, немедленно отзовите/перевыпустите его.

## Шаг 6. Разверните бота

После того как `wrangler.toml` содержит правильный KV ID и в GitHub добавлены `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`, сделайте commit/push в ветку `main` (или откройте **Actions → Deploy Telegram bot → Run workflow**). Первый deploy опубликует Worker; шаг регистрации webhook будет пропущен, если `WORKER_URL` ещё не задан. Скопируйте URL Worker из вывода Actions или панели Cloudflare. Затем добавьте секреты Worker в Cloudflare, а все пять GitHub secrets из списка выше — в GitHub. Запустите workflow ещё раз: теперь он должен развернуть код и зарегистрировать Telegram webhook.

Если деплой не проходит, проверьте по порядку:

1. KV namespace ID верный.
2. GitHub secrets заполнены без пробелов в начале/конце.
3. Cloudflare API token имеет необходимые права.
4. `WORKER_URL` — URL именно вашего Worker, доступный по HTTPS.
5. Worker secrets добавлены после первого deploy; если добавили позже, повторите deploy.

Откройте URL Worker в браузере. Ответ `Telegram text editor is running.` означает, что Worker доступен. Это не подтверждает, что токены или webhook настроены верно; для этого проверьте GitHub Actions и напишите `/start` боту.

## Использование

- `/start` — приветствие и выбор стиля;
- `/mode` — сменить стиль;
- `/usage` — посмотреть дневной лимит;
- `/help` — справка;
- `/privacy` — сведения об обработке данных.

Выберите режим и отправьте текст. Сейчас бот принимает обычные текстовые сообщения, до 10 000 символов за запрос. Дневной лимит на каждого пользователя: до 10 запросов и до 20 000 входных символов. Лимиты ориентировочные и не являются финансовой гарантией; бесплатные квоты Gemini также применяются отдельно.

## Безопасность и ограничения

- Доступ выдаётся только ID из `ALLOWED_TELEGRAM_IDS`.
- Webhook проверяет секретный заголовок Telegram.
- Тексты не записываются в KV; в KV сохраняются только режим и дневной счётчик.
- Не отправляйте пароли, данные банковских карт, медицинские документы или конфиденциальную информацию.
- Бот использует бесплатные квоты API, которые могут меняться; при превышении квоты запрос вернёт ошибку.
- Счётчик KV не является финансовым биллингом и при редких одновременных запросах может быть приблизительным. Для 2–5 друзей этого достаточно как базовой защиты, но это не защита от всех возможных злоупотреблений.
- Не загружайте `.env`, `.dev.vars`, токены или API keys в GitHub.
- Чтобы убрать доступ у друга, удалите его ID из `ALLOWED_TELEGRAM_IDS` и сделайте deploy заново.

## Если бот перестал отвечать

1. Проверьте GitHub → Actions на ошибки.
2. Проверьте доступность бесплатной квоты Gemini и правильность API key.
3. Убедитесь, что Worker URL не менялся и webhook зарегистрирован.
4. После изменения Worker secrets запустите повторный deploy.

## Файлы проекта

- `src/index.js` — логика Telegram-бота и редактура;
- `wrangler.toml` — настройки Cloudflare Worker и KV;
- `.github/workflows/deploy.yml` — автоматический deploy при обновлении `main`;
- `.env.example` — пример названий секретов, без настоящих ключей.
